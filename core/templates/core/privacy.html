Privacy

Your information, plainly explained

Last updated: {% now "F j, Y" %}

Information you send

The contact form asks for your first name, last name, email address, service needed, and project brief. The project inquiry form asks for your name, email address, project type, budget range, timeline, and project description; company and reference links are optional. The application records when each submission was created. Project inquiries also receive an internal status, initially “new”, for staff tracking. A hidden anti-spam field is used by the project inquiry form and is not stored.

If you have a client portal account, the site also stores account details (username and email), a password hash, and the project information attached to your account. Project information can include a project title, summary, status, milestones, dates, and resource links.

Please do not send passwords, payment details, or other sensitive information through an inquiry form.

How information is used

Inquiry details are available to the site operator to review and respond to project requests. Portal details are used to provide account access to the project information shared with that account. The application does not configure analytics or advertising tools.

Storage and access

Application records are stored in the database configured for this deployment. Local development can use SQLite; the deployed site is intended to use hosted PostgreSQL. The application is deployed through Vercel, and the database provider selected by the site operator processes stored records. Staff accounts can view inquiries and manage records through Django administration. Client accounts can view only projects assigned to them.

Passwords are handled by Django authentication and stored as password hashes, not as readable passwords. The inquiry forms do not accept file uploads.

Cookies and browser storage

Django may set a session cookie for signed-in portal users and a CSRF cookie to protect form submissions. The browser-side portfolio preview tool can save its local content override in this browser's local storage under eddyforge_content_override. That preview data stays in the browser and is not a server-side publishing mechanism. The application code does not use session storage for authentication.

External services and links

Pages load the Inter font through Google Fonts (fonts.googleapis.com and Google-hosted font files such as fonts.gstatic.com), Bootstrap Icons from jsDelivr (cdn.jsdelivr.net), and code-highlighting assets from cdnjs (cdnjs.cloudflare.com) on article pages. These providers may receive standard browser request information when those assets load. The site also links to WhatsApp, GitHub, and LinkedIn; those services receive information if you follow their links.

If a booking URL is configured, the project confirmation page embeds that external booking page. The configured booking provider may receive browser request information and data you enter there. Portfolio content may also link to external project sites or load images from URLs configured by the site operator.

Analytics and retention

No analytics integration is present in the application code. Inquiry and account records remain in the configured database until the site operator removes them. A specific retention period has not been set out here.

Questions or requests

To ask about information held in connection with an inquiry, or to request a correction or deletion, contact {{ contact_email }}. Include enough information to identify the request, but do not send passwords or payment details.
