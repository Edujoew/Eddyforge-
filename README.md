# Eddyforge

Eddyforge is Johnny Edwards's full-stack development portfolio. Django serves the pages and stores inquiries; portfolio content is managed through Django admin and seeded from `core/static/core/content.json`.

## Local development

Use Python 3.11+ and PowerShell from the project root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:DJANGO_DEBUG = "True"
$env:DJANGO_SECRET_KEY = "local-development-key"
python manage.py migrate
python manage.py runserver
```

The initial development secret is used only while `DJANGO_DEBUG=True`; production startup fails clearly if `DJANGO_SECRET_KEY` is absent. Create an admin user with `python manage.py createsuperuser`.

## Deployment configuration

Vercel builds static assets with `python manage.py collectstatic --noinput` and serves Django through `eddyforge_project/wsgi.py`. WhiteNoise handles compressed static files. Configure these variables in the deployment environment:

| Variable | Purpose |
| --- | --- |
| `DJANGO_SECRET_KEY` | Long, random Django signing secret; required outside debug mode. |
| `DJANGO_DEBUG` | Set to `False` in production. |
| `DJANGO_ALLOWED_HOSTS` | Comma-separated hostnames; `.vercel.app` is included automatically. |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | Comma-separated fully qualified origins, including scheme, e.g. `https://example.com`. |
| `DATABASE_URL` | Hosted PostgreSQL connection URL. Leave unset for local SQLite. |
| `SITE_URL` | Canonical public origin, e.g. `https://example.com`, without a trailing slash. |
| `BOOKING_URL` | Optional booking provider URL. |
| `CONTACT_EMAIL` | Public privacy/contact address. |

HTTPS-only session and CSRF cookies are enabled when `DJANGO_DEBUG=False`. For hosted PostgreSQL, configure a persistent managed database: Vercel's filesystem and SQLite files are not durable. PostgreSQL connections use `conn_max_age=0` and disable server-side cursors for pooled/serverless compatibility.

## First-time hosted database setup

Run these commands from your machine after installing the requirements and setting environment variables. Use the provider's direct (non-pooled) connection URL for migrations when available:

```powershell
$env:DATABASE_URL = "postgresql://USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
$env:DJANGO_SECRET_KEY = "REPLACE_WITH_A_RANDOM_SECRET"
$env:DJANGO_DEBUG = "False"
$env:DJANGO_ALLOWED_HOSTS = "example.com,www.example.com"
$env:DJANGO_CSRF_TRUSTED_ORIGINS = "https://example.com,https://www.example.com"
$env:SITE_URL = "https://example.com"
$env:CONTACT_EMAIL = "you@example.com"
python manage.py migrate
python manage.py createsuperuser
python manage.py import_content
```

Never commit connection strings, passwords, or production secrets. Add the same required variables in Vercel before deploying. Run database commands locally against the hosted database by setting `DATABASE_URL` in that PowerShell session.

## Application structure

- `eddyforge_project/` — Django settings, URL configuration, WSGI and ASGI entry points.
- `core/` — pages, models, admin, migrations, templates and static files.
- `core/static/core/content.json` — source content for the client-rendered portfolio areas and content importer.
- `staticfiles/` — generated by `collectstatic`; do not edit directly.
- `BUILD_PROGRESS.md` — implementation status and operator handoff checklist.
